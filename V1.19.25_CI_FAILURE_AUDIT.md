# V1.19.25 — CI failure audit / FIX1

Date: 2026-10-06

## Root cause found in supplied validation logs

The supplied GitHub Actions log does **not** show an Android runtime crash. The release-validation job stops in the static validation stage, before `Generate runtime maps`, `Build FBD105`, `gradle :app:assembleDebug`, and APK upload.

The exact failing assertion is in `tools/test_olfactory_input_map.py`:

```text
assert 'val local = when (mechanosensorySide[i].toInt())' in MAIN
```

V1.19.25 intentionally changed that implementation when adding anatomical mechanosensory site routing. The current runtime code now separates:

- `side = mechanosensorySide[i].toInt()`
- `site = mechanosensorySite[i].toInt()`
- `local = when (site) { ... }`
- `externalRateHz[i] = (local * 130f + mechGlobal * 12f).coerceIn(0f, 150f)`

The test was stale and still asserted the pre-V1.19.25 implementation. Therefore CI failed even though the new obstacle-contact structural audit passed.

## Fix

Updated `tools/test_olfactory_input_map.py` to assert the V1.19.25 anatomical site/side implementation and the current bounded sensory-rate encoder instead of the obsolete source spelling.

No neural graph, FBR-10 topology, motor command, wall-turn rule, or physical actuator behavior was changed by this fix.

`4d643835b7e924ace93fb4b36500a1195d4f8129318da79a5f4df84bb6dc8cda`

# V1.19.25 — OBSTACLE INTERACTION AUDIT

## Problem observed
In V1.19.24 the fly could maintain locomotion while remaining pressed against an arena wall and repeatedly translate along the wall without changing heading. The video supplied with the release shows the failure mode directly.

## Root cause
The collision layer correctly refused to synthesize a turn, but the sensory representation of the collision was too coarse:
- mechanosensory input was mostly side-unknown in the reduced FBR-10 map;
- front/leg contact was collapsed into generic wall pressure;
- the retained connectome therefore did not receive a sufficiently anatomical, spatially resolved obstacle signal.

## V1.19.25 correction
The environment now remains outside the motor actuator. Physical contact is converted into external sensory rates only:
- retained LEG mechanosensors receive per-foot wall contact;
- retained ANTENNAL mechanosensors receive anterior/antenna contact;
- WING/HALTERE/BODY/OTHER mechanosensors receive body-side wall pressure;
- official annotation fields are used to recover lateral identity when somaSide/rootSide are absent;
- no heading, yaw, gait phase or motor activation is written by the collision code.

The connectome still decides whether this mechanosensory input changes descending/VNC activity and therefore locomotion.

## Validation
Static architecture tests pass. Python syntax checks pass. Android/Kotlin compilation still must be confirmed by GitHub Actions.

This change does not add neurons, synapses, or synthetic motor commands.

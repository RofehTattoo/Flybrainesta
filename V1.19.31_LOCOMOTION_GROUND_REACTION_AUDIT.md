# V1.19.31 — Locomotion / ground-reaction audit

## Trigger

V1.19.30 CI was fixed successfully, but the supplied runtime video showed the fly reaching a boundary, remaining trapped for long periods, and failing to track food. The previous source-contract tests did not exercise the physical invariants that distinguish a genuine ground-reaction interface from a scalar locomotor controller.

## Findings in V1.19.30

1. The six-leg actuator computed forward acceleration from a scalar `propulsive` term and lateral acceleration from `supportBalance * turnDrive`.
2. Yaw was ultimately driven through a steering target/fallback path rather than being solely the integral of the six individual foot force moments.
3. Wall contact supplied torque but did not provide a complete translational reaction-force path.
4. The old wall recovery path could bias the body back toward the boundary while clamping position, which is consistent with boundary following/sticking.
5. The V1.19.30 static tests verified source patterns but did not test net-force consistency, symmetric-gait yaw, or whether a wall normal force can create a physically valid body response.

## V1.19.31 correction

The mechanical layer now uses: `six measured VNC leg drives -> six independent foot states -> stance foot slip -> bounded ground-reaction force -> net body force + r×F torque`.

Wall contact is resolved in world coordinates from actual foot penetration. A stance foot can generate a wall normal reaction whose force and moment are applied to the body. The generic wall constraint only removes velocity directed through the wall and preserves tangential motion. It does not write heading, gait phase, motor activation, or body position recovery.

A bounded negative body-frame forward velocity is now allowed (`MAX_BACKWARD_SPEED = 0.80`) so that a mechanically generated wall-normal reaction is not immediately discarded by a non-negative velocity clamp. This is a physical capability of the mechanics layer, not a wall-escape command.

## Connectome boundary

No FBC103 selection, ORN census, synthetic edge, food-to-motor shortcut, or action-to-position path was changed by this correction. The active reduction remains `FBR-10-OLF2-MOTORROUTE`.

## Validation performed locally

- Python source-contract tests for release version, food chain, closed-loop boundary, locomotion, adaptive six-leg mechanics, and the new ground-reaction/wall-contact purity test: PASS.
- `compileall` for Python tooling: PASS.
- `kotlinc` standalone compilation of `LeggedSensorimotorActuator.kt`: PASS.
- A standalone no-wall symmetric-drive harness showed near-zero mean lateral drift and small bounded yaw drift; this is a mechanics smoke test, not biological validation.
- A standalone wall-contact harness confirms the new wall reaction produces mechanically signed velocity/torque inputs, but a purely symmetric head-on wall contact does not autonomously invent a turn. This is intentional: release behavior must come from neural mechanosensory feedback rather than a hidden wall controller.

## Remaining release limitation

The Android APK itself and the canonical MaleCNS rebuild were not executed in this local audit environment, because the checked-in FBC103 is a bootstrap artifact and the pinned MaleCNS source bundle is not present locally. Therefore this report does not claim that V1.19.31 has been behaviorally validated on-device. The next decisive test is an APK run with telemetry for mechanosensory L/R, DN L/R, VNC/MN L/R, six-leg loads, wall-contact duration, heading and food distance.

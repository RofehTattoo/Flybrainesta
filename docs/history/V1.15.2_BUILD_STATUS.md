# V1.15.2 build status

## Implemented

- VNC semantic layer is generated from the exact SHA-pinned MaleCNS v1.0 annotation Feather.
- Runtime uses `vnc_motor_semantics.tsv` instead of the heuristic FBC103 motor-role byte for body semantics.
- Official anatomical side is applied to VNC motor body coupling.
- Anatomical classes: LEG/WING/ABDOMEN/NECK/HALTERE/OTHER.
- `TTMn` is WING with functional tag JUMP; JUMP is not an anatomical class.
- FBC103 remains byte-for-byte frozen.
- FBD104 generation remains separate and unchanged.
- VNC-01..06 validation is encoded in CI.

Therefore the repository is **CI-ready but not locally APK-validated**. The GitHub Actions workflow downloads the exact official Feather, verifies its SHA-256, generates the 708-row semantics asset, validates VNC-01..06, generates/validates FBD104, and only then compiles the APK.


## CI fix — 2026-09-21

The first CI attempt failed in the VNC semantics step because `feather.read_feather()` implicitly required pandas. V1.15.2 now uses the Arrow-native `feather.read_table()` API and does not require pandas for this pipeline. The official annotation SHA and FBC103 SHA remain unchanged.


## CI correction — official blank `class` field

The first pandas-free CI run reached the real annotation audit and stopped on
bodyId 164190 (MNad21), where the official Feather has `class` blank while the
measured motor `subclass` is `ad`. This is not a missing neuron or a malformed
Feather. V1.15.2-FIX2 therefore derives anatomical class from the measured
motor subclass vocabulary and independently validates every generated row
against the official Feather. A populated official `class` must agree with
that subclass-derived class; a blank class is recorded as
`classSource=subclass_completion`.

The Android loader now validates the exact TSV schema, and the HALTERE
telemetry accumulator bug in `driveBody()` was also corrected: it is reset
per tick instead of accumulating across the entire simulation.


### FIX3 — VNC census bug
The VNC semantics builder now counts and emits the effective anatomical class (`anatomicalClass` / completed `class`) rather than the nullable raw MaleCNS `class` field. This prevents the valid all-blank raw `class` field from producing a false `{'': 708}` census. `classSource` preserves whether the value came directly from `class` or was completed from the official motor `subclass` vocabulary. No FBC103/FBD104 data are changed.

### FIX5 — canonical class vocabulary

The CI census reached the real official annotation data and exposed only a
naming mismatch: MaleCNS uses the anatomical class value `abdominal`, while the
FlyBrain canonical runtime vocabulary is `ABDOMEN`. FIX5 normalizes this through
an explicit alias map, retains `classSource`, reports raw and canonical class
censuses separately, adds dependency-free normalization tests, and hardens the
Android loader against TSV class/role inconsistencies. No structural or dynamic
connectome artifact is modified.


## FIX6
The CI failure `official retained VNC motors=28` was traced to a one-byte-short FBC103 parser in `validate_vnc_motor_semantics.py`. The builder used a 26-byte node record while the validator consumed 25 bytes. This desynchronized every record after the first. FIX6 centralizes the parser in `tools/fbc103_reader.py` and adds a self-test. No FBC103 bytes were changed.


## FIX8 — frozen validator dependency isolation

The CI reached the frozen FBR-10 validation stage after VNC-01..06 and FBD104 validation passed, but `validate_frozen_connectome.py` imported NumPy even though this validation only requires the frozen binary format and structural invariants. FIX8 removes that dependency, delegates node parsing to the shared `tools/fbc103_reader.py`, and validates the 2,064,951 directed structural edges with the Python standard library. CI now runs both the shared-reader self-test and a dependency-free validator smoke test before the frozen artifact validation. FBC103/FBD104/VNC semantics are unchanged.

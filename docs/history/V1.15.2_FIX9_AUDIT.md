# V1.15.2 FIX9 — VNCSEM runtime header regression

## Root cause
The Android loader expected the VNC semantic TSV header using `\\t` in the Kotlin
source, which produces a literal backslash+t sequence at runtime. The generated
TSV correctly contains real tab characters, so `loadVncMotorSemantics()` rejected
the header and `loadMeasuredConnectome()` failed closed, resetting the displayed
structural/dynamic edge counts to zero.

## Fix
The expected header now uses Kotlin's `\t` escape, producing real tab characters
at runtime. A CI source-level regression check prevents the literal `\\t` form.

## Scientific scope
No FBC103/FBD104 data, neural dynamics, graph, weights, or VNC semantic data were changed.

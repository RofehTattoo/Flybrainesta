# FlyBrain V1.13 — Neural activation fix

## Root cause found

The V1.13 runtime injected external sensory input directly into the LIF membrane array `v[]` inside `sense()`.

The neural clock advances in 20 ms steps (`dt = 0.020 s`) and the membrane leak used:

`v += ((V_REST - v) * 50 - adapt) * dt`

With `tau_m = 1/50 = 0.020 s`, the Euler leak factor is exactly `50 * 0.020 = 1`. Therefore any voltage that `sense()` had just added to `v[]` was pulled back to `V_REST` before the threshold test. The stimulus was effectively erased every neural tick.

This explains the observed combination:

- CONNECTOME OK
- stimulus buttons work
- no visible active neurons
- Spikes/s = 0
- motor = 0%
- no body displacement

## Correction

Sensory input is now stored in `sensoryCurrent[]` and applied inside the LIF update **after** the membrane leak and before threshold evaluation.

The causal chain is therefore:

stimulus → sensory drive → sensory LIF spike → retained MaleCNS edges → downstream activity → DN/VNC motor activity → body movement

No neuron, edge, behavioral command, random locomotion oscillator, or stimulus-to-body shortcut was added.

## Additional protection

The Android loader now requires the binary edge count to match `GeneratedConnectomeMeta.EDGES`. A stale or mismatched connectome binary will fail visibly instead of silently running with inconsistent metadata.

## Diagnostics

The UI now exposes smoothed measured activity for:

- S = sensory population
- C = OTHER/central population
- DN = descending neurons
- M = VNC motor population
- In = peak external sensory drive

These values are read-only diagnostics and do not feed back into the simulation.

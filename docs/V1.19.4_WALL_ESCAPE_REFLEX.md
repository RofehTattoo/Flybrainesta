# FlyBrain V1.19.4 — wall escape reflex

## Root cause found
V1.19.3 removed the outward velocity at the wall and then damped yaw. With a
head-on collision, tangential velocity was zero, so the neural network had to
generate the complete reorientation on a later frame. In the observed lock
case, the motor system continued producing forward drive while the mechanical
constraint continuously deleted that forward velocity. The result was a fly
pressing against the boundary without changing course.

## Correction
`LeggedSensorimotorActuator.applyWallConstraint()` now:
1. removes only the penetration component;
2. preserves tangential slide;
3. derives an escape-turn side from collision geometry and actual bilateral
   leg imbalance;
4. alternates only between separate neutral head-on contact episodes, with no RNG;
5. creates a short-lived yaw target through the existing mechanical yaw state;
6. unloads forward propulsion briefly on a strong head-on impact;
7. applies a small bilateral gait-phase asymmetry so the turn is expressed through
   the same six-leg actuator.

MainActivity still integrates `heading += yawRate * dt`; it does not directly set
the heading on collision.

## Expected behavior
A fly travelling into a wall should decelerate, begin turning within a few
frames, slide/arc away from the boundary, and resume forward locomotion. A wall
parallel to one side should cause a turn away from that side rather than a
perpendicular bounce. Corners should no longer pin the fly indefinitely.

## Scope
The FBR-10/FBR-10-OLF2-MOTORROUTE neuron/edge data are unchanged.

# V1.15.2 build status

## Implemented

- VNC semantic layer is generated from the exact SHA-pinned MaleCNS v1.0 annotation Feather.
- Runtime uses `vnc_motor_semantics.tsv` instead of the heuristic FBC103 motor-role byte for body semantics.
- Official anatomical side is applied to VNC motor body coupling.
- Anatomical classes: LEG/WING/ABDOMEN/NECK/HALTERE/OTHER.
- `TTMn` is WING with functional tag JUMP; JUMP is not an anatomical class.
- FBC103 remains byte-for-byte frozen.
- FBD104 generation remains separate and unchanged.
- VNC-01..06 validation is encoded in CI.

## Local verification

Passed locally:

- Python syntax checks for the new semantic build/validation scripts.
- MainActivity delimiter balance check (braces, parentheses, brackets).
- No remaining `MOTOR_JUMP` anatomical constant references.
- FBC103 SHA-256 remains `bfadc30fd113c25f9711cce6ef8f6b80e9c139fe6d229965a4adabb94d8b4e60`.
- FBC103 binary is byte-for-byte identical to V1.15.1.

Not executable locally:

- Feather extraction, because the local runtime has no `pyarrow` and no network access to install it.
- Android/Gradle compilation, because the local runtime has no Gradle installation/wrapper.

Therefore the repository is **CI-ready but not locally APK-validated**. The GitHub Actions workflow downloads the exact official Feather, verifies its SHA-256, generates the 708-row semantics asset, validates VNC-01..06, generates/validates FBD104, and only then compiles the APK.


## CI fix — 2026-09-21

The first CI attempt failed in the VNC semantics step because `feather.read_feather()` implicitly required pandas. V1.15.2 now uses the Arrow-native `feather.read_table()` API and does not require pandas for this pipeline. The official annotation SHA and FBC103 SHA remain unchanged.


## CI correction — official blank `class` field

The first pandas-free CI run reached the real annotation audit and stopped on
bodyId 164190 (MNad21), where the official Feather has `class` blank while the
measured motor `subclass` is `ad`. This is not a missing neuron or a malformed
Feather. V1.15.2-FIX2 therefore derives anatomical class from the measured
motor subclass vocabulary and independently validates every generated row
against the official Feather. A populated official `class` must agree with
that subclass-derived class; a blank class is recorded as
`classSource=subclass_completion`.

The Android loader now validates the exact TSV schema, and the HALTERE
telemetry accumulator bug in `driveBody()` was also corrected: it is reset
per tick instead of accumulating across the entire simulation.

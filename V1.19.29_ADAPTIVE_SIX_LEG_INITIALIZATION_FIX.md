# FlyBrain V1.19.29 — Adaptive Six-Leg Initialization Fix

## Root cause found from CI V1.19.28_CI_FIX5

The canonical FBR-10 and the adaptive six-leg source compiled, but four
`LeggedSensorimotorActuatorTest` unit tests failed:

- `noMotorOutput_doesNotAdvanceLegPhasesOrBody`
- `bilateralMotorOutput_drivesSixLegMechanicsAndFeedback`
- `symmetricMotorOutput_hasNoPersistentYawBias`
- `unequalNeuralLegDrive_changesInterLegTiming`

The common cause is that `LeggedSensorimotorActuator.phase` is allocated as a
zero-filled `FloatArray`, while the anatomically defined startup phases live
only inside `reset()`. The class had no constructor/init call to `reset()`.

Consequences:
- a newly constructed actuator started all six legs at phase 0;
- the intended `INITIAL_PHASES` were not active in the first simulation frame;
- equal neural drive therefore began with artificial six-leg synchrony;
- tests expecting the defined startup state and non-degenerate six-leg mechanics failed.

## Fix

Added an `init { reset() }` block to `LeggedSensorimotorActuator`.

This does NOT:
- add a wall response;
- inject a turn;
- add a neural connection;
- modify FBR-10;
- modify ORN/mechanosensory routing;
- modify food/light/danger behavior.

It only makes construction honor the already-defined anatomical startup state.

Release:
- FlyBrain 1.19.29
- versionCode 170

The adaptive six-leg mechanics from V1.19.28 are otherwise preserved unchanged.

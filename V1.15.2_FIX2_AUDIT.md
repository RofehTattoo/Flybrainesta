# V1.15.2 FIX2 — CI diagnosis and surgical corrections

## CI failure analyzed

The pandas-free Feather reader passed. The first real annotation audit then
stopped at:

- bodyId: 164190
- type: MNad21
- superclass: vnc_motor
- subclass: ad
- official `class`: blank

Therefore the previous builder was incorrectly treating a legitimate blank
annotation cell as an unsupported motor class.

## Correct interpretation

The MaleCNS motor `subclass` vocabulary is measured annotation data and maps:

- fl/ml/hl → leg
- wm → wing
- nm → neck
- hm → haltere
- ad → abdominal
- xm → other

The builder now uses `class` when present and uses `subclass` only to complete a
blank class. A populated class that disagrees with the subclass mapping is a
hard failure.

## Additional code audit correction

`MainActivity.driveBody()` previously incremented `haltereActiveCache` directly
for every fired haltere motor. Because that cache was not reset per tick, the
displayed haltere activity accumulated over the entire simulation. The code
now uses a per-tick `haltereActive` counter and assigns the cache once per tick.

## Validator hardening

The VNC validator now independently reads the exact SHA-pinned Feather and
compares the generated TSV against the official motor set row-by-row. A mere
708-row census is no longer sufficient to pass.

It checks:
- exact 708 bodyId set;
- official type/subclass/side/neuromere/exitNerve;
- anatomical class;
- class-completion source;
- TTMn → WING + JUMP functional tag;
- 355 L / 353 R;
- 381/214/67/24/16/6 census;
- FBC103 SHA.

FBC103 and FBD104 remain outside the semantic edit surface.

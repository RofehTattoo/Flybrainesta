# V1.19.28 CI FIX4 — builder version identity

## Root cause
GitHub Actions successfully generated the canonical FBR-10, then `tools/test_v120_locomotion_validation.py`
failed because `tools/build_connectome.py` regenerated `GeneratedConnectomeMeta.kt` with the stale release
identity `1.19.27`. The checked-in Gradle/manifest/test contracts were already at `1.19.28`.

The stale builder also contained `FLYBRAIN_VERSION_CODE = 166`, while the release contract is
`1.19.28 / versionCode 169`.

## Fix
Synchronize the builder itself:
- `FLYBRAIN_RELEASE = "1.19.28"`
- `FLYBRAIN_VERSION = "1.19.28"`
- `FLYBRAIN_VERSION_CODE = 169`
- `APP_VERSION = "1.19.28"`
- `APP_VERSION_CODE = 169`

No connectome selection, edge construction, sensory routing, locomotion mechanics, or wall behavior was changed.

## Consequence
After the canonical FBR-10 build, the generated `GeneratedConnectomeMeta.kt` now retains the same
release identity expected by the structural tests, instead of reverting to 1.19.27.
